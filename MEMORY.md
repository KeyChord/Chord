# Project Environment

- Native Open/Save panels activate `com.apple.finder` chord scope before the real app and global scopes. `app/frontmost/file_picker/native.rs` owns Rust AX/NSWorkspace observers with no polling timer; `file_picker.rs` follows Accessibility permission changes and publishes cached `frontmost.filePickerActive`. Keep the actual app ID for handler context. The chord panel mirrors Finder priority. Main-thread Rust fixture: `cargo run --manifest-path apps/chord-tauri/src-tauri/Cargo.toml --example file-picker -- --ui`; scope coverage: `cargo test --lib file_picker_tests`. All handwritten C/Objective-C and the `cc` build dependency have been removed from Chord. Toggle control uses typed IOKit bindings in `caps_lock.rs`.

- Backslash autosuggest lives in `routes/chords/index/chord-suggestions.ts` and `chords-page.tsx`. The `chord-macros` observable supplies current definitions; incomplete escapes show numbered buffers and named macros (with raw sequence previews) before arrow-key escapes, filtering by typed prefix anywhere in the input. Complete references hide suggestions. Both sidebar and floating layouts show the same list; floating expands only while an escape is pending. Targeted regression tests include filtering, priority, live definitions, and server rendering in both layouts.

- Chord panel layouts live in the `chord-panel` observable and persist as `chordLayout` in `app-state.json`. `0ls`/`0lsl` selects the left sidebar, `0lf`/`0lfb` selects the compact floating bottom panel, and `0lv` cycles. The native nonactivating panel resizes/repositions with the layout; for floating it is transparent and spans the display's visible frame above a 24 pt margin, so the React bar sizes itself to its keys, description, and suggestions (capped at screen width, then it keeps the latest keys visible). While a buffer is typed the bar never narrows (`isDeletionOf` in `chord-tokens.ts`); Backspace or a cleared buffer (execute, cancel, failure) lets it shrink. `chord-input.description` comes from Rust dispatch so it follows app/global priority, macros, regex captures, and repeat/loop prefixes. Keep canonical core TOML and its distribution copy in sync.

- Macros live in `ChordSequence`; `ChordInputManager` hydrates named definitions from `named-macros.json` at startup and saves persistent updates before applying them. Named macros persist unless their name starts with an ASCII digit (0–9); numbered buffers are always temporary. All survive input resets/config reloads. Core setters are `0b<1–9><sequence>` and `0=<name>=<sequence>`. References `\1`–`\9` and `\name=` (leading `=` optional: `\=name=`) expand recursively before repetition, matching, and handler captures. Named references always require their closing `=`, even at the end of input. The leading `=` is needed for names starting with 1–9 (buffers) and, in text only, for names starting with `n`/`up`/`left`/`down`/`right`, because text gives special-key escapes precedence (`parse_text_macro_reference`; user-chosen 2026-10-16 so `/w]\n/wd=1` keeps meaning Enter). Internal expansion always goes through the canonical `ChordMacroName::reference()` (`\=name=`). The UI shows `\name=` unless one of those prefixes needs `=`. Settings → Macros uses the `chord-macros` observable and shared backend mutations to add/edit/rename/delete definitions and edit buffers. Renaming across the digit-prefix boundary updates persistence. Its sequence fields are multiline textareas: each line break is an Enter key press, stored as `\n` notation (`macro-sequence-text.ts` converts both ways); row previews mark every Enter with ↩, including a trailing one, and ⌘Enter saves. Setters save bodies verbatim, but a typed `\1`–`\9` or `\name=` has already been replaced by the macro's contents, so only text/CLI setters keep a live buffer reference. Missing/incomplete references stay pending; recursion, depth, expansion count, and output size are bounded. The 2026-10-15 environment inspection reconfirmed the Tauri/non-React-Native setup below.

- Chord reserves `0` for global meta commands defined in `../chords/@keychord/chords-chord/chords/com/leonsilicon/chord/macos.toml` using `builtin` actions. This protected core file is bootstrapped before optional sources, restored after all package overrides, and cannot be removed or deselected. Only this file can define `0` bindings or built-in actions. `build.rs` embeds it (using the checked-in copy under `apps/chord-tauri/data/chords-chord` when the sibling checkout is unavailable); development reloads read the canonical file. Keep the distribution copy in sync. The file also supplies help and the loop halt template. Leading numeric prefixes repeat input actions; `1` starts an independent loop. Loop IDs and help live in the `chord-execution` observable; input resets preserve loops, while reload/exit stop them. In-flight JS callbacks finish on halt to preserve other handlers in their package worker. `\up`, `\left`, `\down`, and `\right` parse as physical arrow keys.

- Command grammar (`models/chord_command.rs`): `<count><`config`><chord>[⏎<chord>…]`. The backtick config block follows the count (or starts the input) and holds comma-separated options, digits in 100 ms: `d` = one digit, a single delay before the first run only (never per loop iteration; `` `d5`ab `` delays any chord), `i` = one digit per interval between runs, cycled, `0` = immediate (`` 3`d2,i130`/ws] ``). Each option at most once. A quote's block takes only `i`. Handlers keep the window focused at input completion, even after a delay. Enter is an ordinary key everywhere (buffer, `\n` text notation, triggers); the only hardcoded role is that the run parser splits chords at Enter after a count or config block. The user rejected a configurable separator. Loops, configured delays/intervals, and multi-chord runs become a `ChordPlan` (haltable background run in `chord_loops.rs`); plain `12ab` keeps in-task `num_times`. Earlier chords get isolated handler scopes and the typed chord keeps its typing scope; the plan releases all of them when it ends.

- Handler builders (default exports) run once per configuration load, never per execution; repeats and loop iterations call the built handler again. Each queued run with a completed input selects the focused window once (`select_run_window` in `chord_loops.rs`, AX on a blocking thread via `app/frontmost/focused_window.rs`) and stores it in every handler task and plan step as `HandlerChordAction.focused_window_id`, exposed as `this.focusedWindowId` (`null` while typing or when unavailable). Window-targeting handlers must use it instead of re-reading focus per iteration.

- Quotes / insert mode: typing `'` at a step start opens a quote; a buffer ending in an open quote is insert mode (`ChordCommand::Insert`, `ChordInputState.inserting`). The controller (`app/controller/app_mode.rs`) keeps Chord active without Space: Caps+Space → `finish_insert` (appends the closing `'`; `on_normal_mode_started` turns Caps Lock off), Esc → idle (discards everything), other keys → `type_into_quote` (Shift and modifiers from event-ordered `held_keys`, plus the OS Caps Lock toggle read per letter, Mac-style: Caps Lock + Shift stays uppercase; repeats of keys held before insert mode, like Space, are ignored). Quote text lives beside the keys: a typed quote is an adjacent `''` pair in `input`, its text in `quotes` (`ChordInputState`/`ChordInputEvent`), consumed in order by `parse_steps`. Text notation `'abc'` still works for CLI/TOML. `ChordTaskAction::Type { text, intervals_ms }` types via `Key::for_text_char` (US layout, Shift held for shifted chars) in `app/chord_runner/typing.rs`; `` `i#` `` after the quote sets cycled per-character intervals.

- Chord owns the Caps key (implemented 2026-10-16): the input owner remaps Caps 0x700000039 → F20 0x70000006F in system `UserKeyMapping` (`app/keyboard/caps_remap.rs`, state file `com.leonsilicon.chord/caps-remap-v1/state.json` with holder PID+start time and displaced entries), so macOS never toggles Caps Lock and Chord is its only writer. F20 reaches the tap in order (`tap.rs` decodes it as Caps; repeats swallowed; flagsChanged keycode 57 = mapping was removed → reinstall). `caps_lock_guard.rs`: plain tap turns off at key-down, on at release; normal mode keeps it off; chord end / ownership loss restores the pre-Chord state; insert-mode toggles aren't kept. Caps events are applied on the controller thread before routing. Secure Input fallback: Carbon hotkey F20 (`caps_hotkey.rs`, only fires when the tap can't see the key). Crash safety: launchd agent `<identifier>.caps-guardian` (`caps_guardian.rs`, hidden `chord __caps-guardian --state`, KeepAlive PathState on the state file, kqueue on holder exit) — verified end-to-end with a scratch agent. No raw HID listener, no polling, no timing margins. Lock-state reports from `IOHIDSetModifierLockState` (keycode 255 per keyboard, then the next key's code) are recognized in the tap by "only the AlphaShift flag changed vs. the previous device event" and rewritten in place to keycode 57 (first report) or swallowed (repeats), owner only — no app list. Input Monitoring is no longer required (Accessibility covers the active tap; IOHIDCheckAccess reports listen access granted for Accessibility-only apps). VoiceOver warning: `app/keyboard/voice_over.rs` + Activation Trigger settings card, shown when the VoiceOver4 domain exists and `SCRKeysToUseForVOModifier` != 0. Avoid spawning processes in lib tests: two such tests made the parallel lease tests fail in 4 of 12 runs (0 of 12 without), likely because a child mid-spawn holds their lock fds.

- Typed escapes (`models/chord_escape.rs`) never auto-expand: a Backslash key in the buffer keeps the input pending until Tab (`select_escape`) replaces the trailing escape with a special key it spells exactly, else the first match: named macros in name order matched with or without the leading `=` (full expansion inlined), then `\up`/`\left`/`\down`/`\right`/`\n`. Complete macro references are the exception: typing a buffer's digit (`\1`–`\9`) or a named macro's closing `=` (`\name=` or `\=name=`), as an unshifted or shifted press, immediately replaces the reference with its full expansion (`expand_typed_reference`, called by the input manager whenever a key is appended). Unexpandable references stay as typed; undefined ones make execution fail with "`<ref>` references an undefined macro" (`undefined_reference`), and leftover buffer references in text still expand at dispatch (`expand_typed_input`). Text (TOML, CLI via `ChordMacros::resolve_named`) still parses notation directly. The frontend suggestion list marks the same `active` entry.

- Failed executions (CapsLock, Space release, shifted completion) keep the input on screen: `ChordInputManager::fail_input` moves it to `selected_input_event` and sets `chord-input.error`, which the panel renders as red keys with the message in place of the chord name. `ChordSequenceDispatch.error` explains unresolved input (no chord found, chord named within sequences, pending/escape awaiting Tab); chords that only handle keyboard events are not errors. Resolve errors and later handler/loop failures also set it, guarded by an execution counter so only the still-shown chord is marked. Every state literal that clears `selected_input_event` must also clear `error`.

- 2026-10-12 crash investigation: reproduced NodeSwift 1.5.1's `NodeExecutor.enqueue` abort after an async `NodeActor` → `MainActor` hop with multiple addon environments. The tray and menu packages in `../chords/@keychord/` now return promises from synchronous NodeFunction entrypoints and capture an explicit NodeAsyncQueue for completion. Do not reintroduce async NodeFunction wrappers around MainActor work. Regression: `CHORD_NATIVE_TEST_HOST=<Chord executable> bun test __tests__/actor-queue.test.ts` from the tray package.
- Caps+Space activation uses `CapturedKeyEvent`'s Caps state at capture time; queued Caps events must not overwrite the newer physical HID state. Native artifact staging uses rename so rebuilds preserve images mapped by a running process.
- 2026-10-13: Fixed the same NodeSwift missing-queue abort in iPhone Mirroring using synchronous NodeFunction entrypoints, captured NodeAsyncQueue handles, and explicit promise completion. The Apple read-only actor-queue regression validates 500 value/void/error completions with multiple addons. Package workers now have stable supervisors that restore handler factories in registration order after crashes/timeouts, retain logical handler IDs, and never replay interrupted actions. Retry backoff is 250 ms–30 s and resets after a healthy minute; stop/unload prevents respawn. Tests: cargo test --lib (119 pass), supervisor_ --ignored (2 pass), package_faults_are_contained --ignored (1 pass).

- App IDs (`app/desktop_app/app_identity.rs`): bundle ID, else for a bare executable (macOS reports `bundleIdentifier` nil even with an embedded plist or custom signing ID) a `CFBundleIdentifier` from `__TEXT,__info_plist`, else a non-ad-hoc signing identifier, else the app ID of a chords file that claims the executable's file name with top-level `executables = [...]`. Ad-hoc identifiers are link-time file names (Cargo hashes them per build; Go uses `a.out`), so they are ignored. `ChordPackageManager` rebuilds the executable→app-ID claims after every package write (package priority wins) and calls `frontmost().refresh()`; `AppFrontmost` keeps the identity and resolves under its lock. Frontmost tracking, lifecycle events, `focused_window_id`, and `getAppWindows` (via the `AppProcessIds` host request; CLI mode falls back to bundle IDs) all resolve through it. `NSWorkspace.openApplication(at:)` opens a bare executable in Terminal, so relaunching one is unsupported. Developer-ID interpreters such as `node` resolve to their own ID, shared by every process they host.

- Personal packages (2026-10-29): every visible folder in `~/.chord/packages/` is a chord package (`PersonalPackageRegistry`, `chord_package_registry/personal.rs`); `ChordPackageManager::init` creates `default` (starter `chords/macos.toml`) when missing. They import after every other source, so they override same-name packages, and `reload_once` moves them to the front of the package `OrderMap` in folder-name order, so their chords win within each scope (dispatch keeps first-match priority). A folder that fails to import, or that loads under a name an earlier folder took, is skipped and reported. `ChordPackageManagerState` carries `errors` (per-package load errors from the last reload, empty lists dropped) and `personalPackages` (`dirname`, loaded `name`, import `error`). Settings → My Chords (`routes/settings/personal/index`) lists packages and their `.toml` chords files, keeps unsaved drafts per file, and edits them in a CodeMirror 6 editor (`components/ui/code-editor`, lazy-loaded so it stays out of the chord panel's bundle; exact-pinned `@codemirror/*`, skipping the `codemirror` meta package's stray 6.65.7). Every edit calls `check_chords_file` (the loader's TOML + `ParsedChordsFile` checks, UTF-16 spans from `toml::de::Error::span`); only the reply for the latest contents is applied, so there is no debounce. Saves re-check, refuse to overwrite a file that changed on disk since the editor opened it (`expected` contents; `None` = create, fails if it exists), write via temp file + rename at the symlink target with the old permissions, then reload. The loader skips hidden entries in `chords/` and `js/`, since a binary `.DS_Store` (Finder) would fail the whole package import. Resolvers use `AppError::detailed` so errors keep their context chain.
